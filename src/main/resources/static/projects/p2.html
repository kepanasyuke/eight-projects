JPA без N+1

Одна и та же выборка задач в четырёх вариантах: наивный обход связей, fetch join, EntityGraph и DTO-проекция. Число SQL-запросов измеряется статистикой Hibernate.

HibernateСтатистика запросовfetch joinEntityGraphDTO-проекция@Version
Проект 02 p2.svg

Что реализовано

  • Проблема воспроизводится — naive-вариант читает задачи и дёргает assignee и notes в цикле: число запросов растёт вместе с выборкой.
  • fetch join и EntityGraph — Связи загружаются одним запросом; для страниц используется EntityGraph, чтобы не ломать пагинацию.
  • DTO-проекция — Конструкторное выражение selects только нужные поля и считает notes через size(), без сущностей в контексте.
  • Оптимистичный контроль — @Version на сущности: конкурентное обновление возвращает конфликт вместо тихой перезаписи.
  • Пессимистичная блокировка — SELECT FOR UPDATE через @Lock(PESSIMISTIC_WRITE) с удержанием на заданное время.
