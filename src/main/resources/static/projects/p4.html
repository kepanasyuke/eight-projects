Многопоточность под контролем

Параллельные вызовы, тайм-ауты, потерянные обновления, дедлок и перегрузка пула — каждый сценарий воспроизводится и измеряется, а не описывается словами.

ExecutorServiceCompletableFutureorTimeoutAtomic-классыReentrantLockAbortPolicy

Что реализовано

  • Пул с ограниченной очередью — ThreadPoolExecutor на 8 потоков и очередь 64; AbortPolicy явно сообщает о перегрузке вместо бесконечного роста очереди.
  • Тайм-ауты вместо ожидания — CompletableFuture.orTimeout ограничивает внешний вызов, TimeoutException возвращается клиенту как ошибка.
  • Гонка видна в цифрах — Счётчик long под нагрузкой теряет обновления, AtomicLong — нет: разницу показывает тот же прогон.
  • Дедлок и его лечение — Немаркированный захват двух ReentrantLock даёт дедлок, упорядоченный захват — нет.
  • Честные имена потоков — NamedThreadFactory даёт предсказуемые имена eight-worker-N, по ним читается thread dump.

Фрагмент кода

                    
                

                
@Bean(name = "eightExecutor", destroyMethod = "shutdown")
public ThreadPoolExecutor eightExecutor(@Value("${eight.concurrency.pool-size:8}") int poolSize,
                                       @Value("${eight.concurrency.queue-capacity:64}") int queueCapacity) {
    ThreadPoolExecutor executor = new ThreadPoolExecutor(
            poolSize, poolSize, 60L, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(queueCapacity),
            new NamedThreadFactory("eight-worker-"),
            new ThreadPoolExecutor.AbortPolicy());
    executor.allowCoreThreadTimeOut(true);
    executor.prestartAllCoreThreads();
    return executor;
}
