Брокер, повторы и Outbox

Семантика Kafka и RabbitMQ в одном прогоне: топик, партиции, группы потребителей, оффсеты, ограниченные повторы, DLQ и дедупликация, плюс Transactional Outbox для согласования записи и отправки.

Kafka-семантикаack/nackRetryDLQДедупликацияTransactional Outbox

Что реализовано

  • Партиции и группы — События раскладываются по партициям, каждый потребитель в группе получает свою долю, оффсеты сдвигаются только после обработки.
  • Ограниченные повторы — Неудачная обработка повторяется до настроенного предела, затем сообщение уходит в DLQ, а не крутится бесконечно.
  • Дедупликация — Повторная доставка с тем же идентификатором распознаётся и не применяется дважды — at-least-once превращается в эффект ровно одного применения.
  • Outbox вместо dual write — Событие пишется в таблицу outbox_message в той же транзакции, что и бизнес-изменение, и публикуется после коммита отдельным публикатором.
  • Наблюдаемое состояние — Эндпоинт state показывает оффсеты, размеры очередей и содержимое DLQ после прогона.

// Transactional Outbox: событие сохраняется в той же транзакции,

public void markSent() {
    this.status = Status.SENT;
    this.sentAt = Instant.now();
    this.attempts = this.attempts + 1;

Как читать результат

                
Сравните два прогона: с poison=true сообщение после исчерпания повторов попадает в DLQ, с poison=false — обрабатывается и подтверждается.
