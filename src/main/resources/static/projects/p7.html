Подпись, ключи и сертификаты

Формирование и проверка подписи через JCA/JCE, паспорт сертификата из PKCS12-хранилища, проверка срока действия и цепочки, демонстрация подмены данных.

SignaturePKCS12 KeyStoreX.509Проверка цепочкиSHA-256Готово к КриптоПро JCP

Что реализовано

  • Алгоритм вынесен в конфигурацию — Signature.getInstance берёт имя алгоритма из настроек: подмена на ГОСТ-алгоритм КриптоПро не требует правки кода, только провайдера и имени.
  • Ключи из KeyStore — PKCS12-хранилище загружается один раз, приватный ключ и сертификат достаются по alias.
  • Проверка подписи с причиной — VerifyReport различает SIGNATURE_INVALID, CERT_EXPIRED, CERT_NOT_YET_VALID и SIGNATURE_MALFORMED — диагностика важнее булева ответа.
  • Подмена данных видна — tamper-сценарий подписывает платёж, меняет сумму и показывает, что проверка падает.
  • Отпечаток сертификата — SHA-256 от encoded-формы сертификата даёт стабильный идентификатор для логов и сверок.

Фрагмент кода

                    
                

                
public SignResult sign(String payload) {
    byte[] data = payload.getBytes(StandardCharsets.UTF_8);
    String signatureBase64 = null;
    try {
        Signature signature = Signature.getInstance(this.signatureAlgorithm);
        signature.initSign(privateKey());
        signature.update(data);
        byte[] signed = signature.sign();
        signatureBase64 = Base64.getEncoder().encodeToString(signed);
    } catch (Exception ex) {
        throw new ApiException("SIGN_FAILED", "Не удалось сформировать подпись: " + ex.getMessage(),
                HttpStatus.INTERNAL_SERVER_ERROR);
    }
    return new SignResult(this.signatureAlgorithm, signatureBase64, data.length,
            this.cachedInfo.subject(), Instant.now());
}

            

            

                
Как читать результат

                
Демо использует RSA-ключ из ресурсов, чтобы проект запускался без лицензии КриптоПро. Для ГОСТ достаточно подключить провайдера JCP/JCSP и указать его алгоритм в eight.crypto.signature-algorithm.
