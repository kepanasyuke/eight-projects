WebSocket и машина состояний

Серверная машина состояний поверх WebSocket: приветственный кадр, валидация команд, запрет недопустимых переходов, лимит размера сообщения и освобождение ресурсов при разрыве.

Проект 08 p8.svg

Что реализовано

  • Соединение с состоянием — При открытии сервер присылает welcome с текущим состоянием и списком допустимых переходов.
  • Переходы проверяются на сервере — Клиент присылает {"command":"IN_PROGRESS"}, сервер сверяет переход с WorkItemStateMachine и отвечает state либо error.
  • Ограничение размера — max-text-message-bytes отклоняет слишком большое сообщение с кодом MESSAGE_TOO_LARGE, размер буфера задан на контейнере.
  • Потокобезопасная отправка — Сессия оборачивается в ConcurrentWebSocketSessionDecorator с тайм-аутом отправки.
  • Ресурсы освобождаются — afterConnectionClosed и handleTransportError удаляют сессию из карты: утечки сессий нет.

Фрагмент кода

                    
                

                
@Override
protected void handleTextMessage(WebSocketSession session, TextMessage message) {
    SessionState state = this.sessions.get(session.getId());
    if (state == null) {
        sendError(session, "NOT_REGISTERED", "Соединение не зарегистрировано сервером");
    } else {
        processMessage(state, message);
    }
}

@Override
public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
    this.sessions.remove(session.getId());
    LOG.info("WebSocket закрыт: {} ({})", session.getId(), status.getCode());
}
